# Contributing

## Prerequisites

- Go 1.26.x (see the `go` directive in `go.mod` for the minimum patch version)
- `goreleaser` (only needed if you want to test a release build locally; CI handles real releases)

## Build

```bash
go build -o redpine .
```

Cross-compile targets used in CI (`.github/workflows/ci.yml`, `build` job):

```bash
GOOS=linux   GOARCH=amd64 go build -o /dev/null .
GOOS=darwin  GOARCH=arm64 go build -o /dev/null .
GOOS=windows GOARCH=amd64 go build -o /dev/null .
```

## Test

```bash
go test ./... -race
go vet ./...
```

CI (`ci.yml`) runs these on a 2-OS matrix (`ubuntu-latest`, `macos-latest`) against Go `1.26`.

## Lint

```bash
go vet ./...
go install honnef.co/go/tools/cmd/staticcheck@latest
staticcheck ./...
```

This mirrors the `lint` job in `ci.yml`.

## Security

`.github/workflows/security.yml` runs on every PR, on push to `main`, and weekly (Monday 06:00 UTC):

- `govulncheck ./...` — Go vulnerability scan (stdlib + dependencies)
- `gosec ./...` — static analysis for security issues
- `gitleaks` — secret scanning

Run `govulncheck` locally before pushing if you touched `go.mod`/`go.sum` or networking/crypto code:

```bash
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
```

## Release process

Releases are cut by pushing a `v*` tag:

```bash
git tag v0.x.y
git push origin v0.x.y
```

This triggers `.github/workflows/release.yml`, which runs [GoReleaser](https://goreleaser.com) (`.goreleaser.yml`) to:

1. Build cross-platform binaries (linux/darwin/windows, amd64/arm64 — no windows/arm64)
2. Publish a GitHub release with archives + checksums
3. Push an updated formula to the `redpine-ai/homebrew-tap` repo, so `brew install redpine-ai/tap/connect-cli` picks up the new version

Don't hand-edit the Homebrew tap — it's generated by the `brews:` block in `.goreleaser.yml` on every tagged release.

## PR checklist

- [ ] `go test ./... -race` passes
- [ ] `go vet ./...` and `staticcheck ./...` are clean
- [ ] New/changed commands have `--help` text and, if user-facing, a README example
- [ ] No secrets or credentials committed (gitleaks will also catch this in CI)
- [ ] Docs updated? README/CLAUDE.md sections touched by this change are still accurate.
